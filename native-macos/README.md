# Glass Terminal

Отдельный терминал для macOS 13+ с прозрачным фоном, настраиваемым скруглением и размытием. Ядро работы с оболочкой написано на C11, окно — на Objective-C/AppKit, эмуляция терминала — xterm.js в системном WebKit.

**Статус:** исходный проект. Ядро C и интерфейс эмулятора проверены на Linux. Сборка Objective-C, прозрачность окна и взаимодействие с macOS требуют проверки на настоящем Mac. Готового проверенного `.app` в архиве нет.

## Сборка на Mac

Нужны macOS 13 или новее и Apple Command Line Tools. Если инструменты ещё не установлены, запустите в стандартном «Терминале»:

```sh
xcode-select --install
```

Дождитесь окончания установки. Распакуйте архив в «Загрузки», затем выполните:

```sh
cd ~/Downloads/glass-terminal
sh build.sh
open "build/Glass Terminal.app"
```

Если папка распакована в другое место, измените путь после `cd`. Сборка создаёт приложение в папке проекта и подписывает его локальной ad-hoc подписью. Интернет, Node.js и Homebrew для сборки не требуются: зависимости уже включены в `resources/vendor`. Права администратора не нужны.

Готовый `.app` можно скопировать в свою папку «Программы». Это самостоятельное приложение; встроенный Terminal.app не изменяется.

## Возможности

- Настраиваемое затемнение фона от 0 до 100%. При 0% фон полностью прозрачный и размытие отключается; текст остаётся непрозрачным.
- Скругления от 8 до 40 точек, непрерывная кривая углов, тонкая рамка, тень, сглаженный текст. В полноэкранном режиме радиус равен нулю.
- Необязательное системное размытие фона через NSVisualEffectView. Его сила определяется macOS, а не отдельным ползунком приложения.
- Окна и вкладки с независимыми PTY-сеансами. Полоса вкладок прокручивается по горизонтали.
- Входная оболочка из учётной записи пользователя, обычно `/bin/zsh`, с аргументом `-l`. Каждая новая вкладка начинает работу в домашней папке. Настройки оболочки и её история используют обычные файлы пользователя.
- Unicode, ANSI/VT-последовательности и true color, альтернативный экран, мышь в программах с поддержкой терминального ввода, bracketed paste. Движок xterm.js подходит для программ вроде vim, less, ssh, top и tmux; их работу именно в этом приложении на macOS ещё нужно проверить.
- Прокрутка на 10 000 строк, выделение, поиск по выводу, копирование и вставка, перетаскивание файлов с экранированием путей для оболочки.
- Изменение размера окна передаётся дочернему процессу через `TIOCSWINSZ`. Ctrl+C передаётся в PTY и прерывает активную программу.
- Вывод идёт через ограниченный буфер C и подтверждения обработки xterm.js. При быстром выводе производитель получает обратное давление вместо неограниченного роста памяти.

Это не полная копия Terminal.app. Здесь пока нет восстановления сеансов после перезапуска, групп окон, разделения панели, импорта его профилей, собственного словаря AppleScript, печати и переноса всех его настроек. Совместимость управляющих последовательностей определяется xterm.js. Штатные команды macOS запускаются установленной оболочкой.

## Оформление и клавиши

Нажмите значок настроек справа в заголовке или **⌘,**. Параметры сохраняются через NSUserDefaults. По умолчанию установлены радиус 26 точек, затемнение 18%, размытие и шрифт 14 точек.

| Действие | Клавиши |
| --- | --- |
| Новое окно / вкладка | ⌘N / ⌘T |
| Закрыть вкладку | ⌘W |
| Вкладки 1–9 | ⌘1…⌘9 |
| Предыдущая / следующая вкладка | ⌘⇧[ / ⌘⇧] |
| Копировать / вставить / выделить всё | ⌘C / ⌘V / ⌘A |
| Найти в выводе | ⌘F |
| Следующее / предыдущее совпадение | Enter / Shift+Enter в поиске |
| Закрыть поиск | Escape |
| Очистить историю вывода | ⌘K |
| Увеличить / уменьшить / сбросить шрифт | ⌘= / ⌘− / ⌘0 |
| Полноэкранный режим | ⌃⌘F или зелёная кнопка |
| Прервать программу | Ctrl+C |

Перемещайте окно за свободную область верхней панели. Размер меняется за край окна. Option сохраняет обычный ввод macOS; режим Option-as-Meta пока не добавлен. Вставка ограничена 1 МиБ за один раз. OSC 8-ссылки открываются по ⌘-щелчку, разрешены `http` и `https`.

При закрытии вкладки с отдельной активной программой появляется подтверждение. Фоновые и отделённые задания этим определением не обнаруживаются. При выходе из приложения подтверждение запрашивается для любых незавершённых сеансов. Закрытие отправляет SIGHUP связанным группам процессов и закрывает PTY; отделённые от сеанса процессы могут продолжить работу по обычным правилам Unix.

## Реализация прозрачности

Окно использует `opaque = NO`, прозрачный `backgroundColor` и маску скруглённого слоя. Прозрачность меняется у фона, а не через `NSWindow.alphaValue`, поэтому текст не выцветает вместе с окном.

Для WKWebView дополнительно используется изолированный вызов KVC `drawsBackground = NO`: это **непубличный параметр WebKit**. Без него некоторые версии macOS рисуют непрозрачную подложку даже при прозрачном CSS. Если WebKit перестанет поддерживать этот параметр, приложение перехватит исключение и запишет сообщение в журнал, но прозрачность может не сработать. Такой проект требует проверки после обновлений macOS и не подготовлен к публикации в Mac App Store.

Все ресурсы WebKit локальные. CSP запрещает сетевые запросы; мост принимает сообщения только от основного локального документа. Данные PTY передаются как байты и не вставляются в HTML. OSC 52 не получает доступ к системному буферу обмена. В приложении нет локального HTTP-сервера или фонового сетевого сервиса.

## Исходники

| Файл | Назначение |
| --- | --- |
| `src/pty.c`, `src/pty.h` | C11: PTY, posix_spawn, неблокирующий ввод-вывод, ограниченные очереди, изменение размера и завершение дочернего процесса |
| `src/main.m` | Objective-C: AppKit-окно, вкладки, WebKit-мост, меню, буфер обмена и настройки |
| `resources/terminal.js` | Настройки xterm.js, поиск и передача байтов |
| `resources/index.html`, `terminal.css` | Локальная страница эмулятора |
| `resources/vendor` | Закреплённые версии зависимостей, лицензии и manifest с SHA-512 npm-архивов |
| `build.sh`, `Info.plist` | Сборка самостоятельного приложения |
| `tests` | Интеграционные тесты и проверка интерфейса эмулятора |

PTY запускается через `posix_spawn` с созданием новой сессии и открытием подчинённого устройства как управляющего терминала. Это избегает небезопасного выполнения Objective-C или аллокатора после `fork()` в уже многопоточном AppKit/WebKit-процессе.

## Проверка

В доступной Linux-среде пройдены 8 интеграционных тестов C и 6 браузерных тестов фронтенда. Подробности и шаги проверки на Mac находятся в `TESTING.md`.

Основные источники API: [NSWindow](https://developer.apple.com/documentation/appkit/nswindow), [xterm.js](https://xtermjs.org/docs/), [передача вывода с обратным давлением](https://xtermjs.org/docs/guides/flowcontrol/), [безопасность xterm.js](https://xtermjs.org/docs/guides/security/).
